9. FILTER LOGIC
==================================================

There are two filter collections.

filters
= AND

any_filters
= OR

Every condition inside filters must be true.

At least one condition inside any_filters must be true.

Conceptually:

filters:
A AND B AND C

any_filters:
A OR B OR C

When both are present:

filters conditions
AND
(any_filters conditions)

==================================================
10. ALWAYS-TRUE CONDITIONS
==================================================

If a condition must always apply, put it in filters.

Example:

"Critical Technical tickets"

means:

priority = Critical
AND
category = Technical

Therefore:

filters = [
  priority = Critical,
  category = Technical
]

any_filters = []

Another example:

"How many Critical tickets are open?"

filters:

priority = Critical
status = Open

==================================================
11. OR / ALTERNATIVE CONDITIONS
==================================================

Use any_filters when the user is expressing alternatives.

Typical language:

or
either ... or ...
one of
any of
either
alternatively

But interpret the sentence semantically.

The presence of the word "or" alone is not enough if it is not expressing
alternative ticket conditions.

For genuine alternatives, use separate any_filters entries.

Example:

"How many tickets are either Critical or High priority?"

Correct:

"filters": [],
"any_filters": [
  {
    "field": "priority",
    "operator": "eq",
    "value": "Critical"
  },
  {
    "field": "priority",
    "operator": "eq",
    "value": "High"
  }
]

This means:

priority = Critical
OR
priority = High

Do NOT create:

"filters": [
  {
    "field": "priority",
    "operator": "in",
    "value": "Critical,High"
  }
]

Do NOT put the alternatives into filters because filters are AND.

==================================================
12. IN OPERATOR
==================================================

The "in" operator is allowed.

When using "in", the value MUST be a JSON array.

Correct:

{
  "field": "priority",
  "operator": "in",
  "value": ["Critical", "High"]
}

Incorrect:

{
  "field": "priority",
  "operator": "in",
  "value": "Critical,High"
}

For simple OR conditions, prefer separate any_filters with eq.

==================================================

These are alternative conditions.

    "field": "resolution_time_hrs",
    "operator": "gt",
    "value": 12

]

The priority condition is always required, so it belongs in filters.

The two "not resolved within" conditions are alternatives, so they belong
in any_filters.

Do NOT change this to AND.
